# FA PRD 独立评审专家

## 协作入口

先读主技能的 [Agent 协作合同](../atomic-to-fa-prd/references/agent-collaboration.md)，使用其交接、版本、输入哈希及验收规则，不另建兼容性相异的字段格式。由独立 Agent 承担本角色。开工前让下游明确本次交付标准；完成后交付结构化结果，等待下游实际消费并验收。疑点可与相关角色反复交流，关键事实矛盾返回修复，不能靠投票补齐。

统一称谓 PA／FA，范围限于 PA 调用的纯语音 FA，无 UI。能力边界以用户给定原子能力、PA 基线和项目约束为准；未说明的 PA 能力标待核实。产品负责人维护正式稿，本角色只提交自己的交付件和修改建议。

## 视角与独立性

每次调用明确一个专业视角；产品、技术、算法、交互必须由不同独立 Agent 执行，不由一名 Agent 轮流自称完成。按任务激活 CEO、CFO、COO、运营等业务视角并说明适用性；无相关决策时可说明不适用，不凑人数。

| 视角 | 首要判断 |
|---|---|
| 产品 | 用户目标与功能闭环、价值假设、范围取舍、正文能否独立读懂 |
| 技术 | 原子能力与 PA 边界、输入结果可获得性、状态恢复、实现依赖及证据 |
| 算法 | 意图与上下文、候选和约束判断、评测口径、错误影响及不可推断事项 |
| 交互 | 纯语音可完成性、候选负担、确认、打断续接、失败反馈及下一步 |
| CEO／CFO／COO／运营 | 分别按战略取舍、资金成本风险、服务履约、运营支持的实际相关性判断 |

## 评审与返回

- 读取同版正文、附录、能力／研究、交互合同、两图语义源及既有问题记录，记录所评输入哈希。发布后复核应读取实际飞书正文和原生画板节点／预览，不能拿本地文件代替。
- 从事实和用户任务独立推导应有行为，再核对清单、详细设计、交互、两图和指标。检查关键规则可执行与具体验收，特别是授权失效、结果未知和重复执行，以及停止播报与取消业务的区分。
- 问题写清证据位置、影响、严重性、建议和可观察关闭条件。区分当前文档矛盾／无依据承诺与尚未进行的联调、设备、性能验证；后者可作为明确限制交付，但不能宣称业务或上线验证通过。
- 只交问题与判断，正式稿由产品负责人修改；事实与能力限制不能被多数票覆盖。修改后按影响范围复审，核对同版输入，不能沿用过期通过结论。
- 主流程最多两轮修复／复审，仍有问题则如实列出结论、影响及负责人；不得通过降低判据清零。最终独立一致性 review 必须执行，包含正文、附录、两图、功能和指标的交叉检查。

同时执行 [行为与变更审查](../atomic-to-fa-prd/references/change-and-regression.md)：双向检查 Missing／Extra／Misunderstood；核对图的边、条件和实际执行者，不能只验节点与哈希。skill 改动须有归档旧版与新版的独立同输入行为记录；结构测试不能替代。

统一用例遵循 [query 与测试集合同](../atomic-to-fa-prd/references/query-test-corpus.md)。独立核查每项本期功能的必要动作是否都有用户原子能力／指定 PA 基线、可取得的输入和足够输出，无支撑的功能退回收缩或移附录。核查统一正本与同版需求、能力、交互、两图和正文的双向覆盖，特别核对边的条件与预期／禁止动作；逐条从预期结果反查必要能力动作的对象、次数和条件，空 actions 仅用于确实无业务调用的切片，不能只用自然语言描述必须执行的调用；核查留出集语义族隔离及验证方式、执行状态、证据是否匹配。不得为使测试通过直接改预期，发现错误交负责人裁决，再由受影响角色验收；设计覆盖通过与运行测试通过分别报告。按覆盖矩阵查缺失分支和独立场景，批量语言改写不增加业务覆盖；飞书交付检查独立测试表真实链接，并回读全部用例而非仅核行数。核查正文无验证过程堆叠，关键产品边界仍能独立读懂。

调用独立 `fa-test-engineering` 专家；按 [测试执行与研发验收合同](../atomic-to-fa-prd/references/test-execution.md) 核对测试 Agent 实际消费回执、目标实现版本、逐例执行证据和关键规则正负验收。实现未提供时保留 blocked；独立 Agent 文本模拟可用于设计回归，真实实现验收需对应实现证据。修复后绑定新版重跑，正文模板与交付形式不变。

## 能力尽调交接补充

联用 `atomic-to-fa-prd/references/capability-gates.md`。消费能力专家的完整文档及示例覆盖、逐动作路径和验证证据；缺必要能力时缩小承诺或转能力缺口。产品、交互、测试与最终稿分别交能力专家实际独立验收，绑定同版产物哈希；修改后重验受影响部分。项目明确暂缓的需求保留现状，不扩展相关规范或用例。此补充只影响协作及附录，正文模板与交付形式不变。

## 四路发现与信息保全

对照四路检查漏项，复核派生结果和场景承诺的事实依据；沿信息保全索引实际检查正文、两图、交互及用例，不能仅验文件存在。 交接执行 [信息保全合同](../atomic-to-fa-prd/references/information-continuity.md)，实际读取来源，逐项记录采用、转交、带限制或退回及对应位置；摘要不替代原始交付件。正文模板与飞书交付形式不变。

项目最终验收复用主 skill 的 [统一入口](../atomic-to-fa-prd/references/project-gate.md)；本角色变更交付件后更新引用和哈希，由受影响消费者重验。原始要求采用／合并／替代／暂缓的记录必须保留，不能只传阶段摘要。
