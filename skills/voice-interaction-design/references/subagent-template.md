# 子Agent PRD模板与交互配置卡 V0.1

生成交互章节以[交付模板](prd-output-contract.md)为准，先按[决策与流程配方](prd-generation-rules.md)作出设计。下方配置卡用于提取需求和记录差异，不要求用户手动填写，也不能替代生成完整章节。

## 使用方式
先整理现有需求，再填配置卡。事实填写来源；未知填待确认；仅对适用项展开。产出正文应独立解释体验与理由，配置卡和编号追溯放附件。

先按[conversational-ux基础适配](conversational-ux-base.md)逐项确定适用规则。每个关键节点填写：触发条件、已知信息、判断、动作、实际话术、用户控制、异常去向和验收结果。确认方式、重试上限、等待时长、分段方式和例外须有业务依据；未知参数标待验证。

## 交互配置卡
| 项目 | 需填写内容 |
|---|---|
| 交互特征与机制 | 根据通用规范的交互维度识别需求；列适用模式和扩展机制、场景参数与例外，无需匹配已知业务目录 |
| 能力组合 | 按能力分类选择查询、记录、感知、位置、持续引导、交易、通信或控制；可多选，写清适用专项规则 |
| 身份与价值 | 子Agent业务名/服务方、目标用户、要解决的任务、成功标准 |
| 范围 | 支持/不支持、容易混淆的功能边界、显式点名服务时如何处理 |
| 入口 | 用户自然表达、指定服务、上次任务续接、已支持事件触发 |
| 参数与上下文 | 必填/可选、来源、授权、有效期、歧义与更正规则 |
| 硬件能力 | 拍照/GPS/音频等是否必需，实际开放能力依据及缺口 |
| 视觉数据 | 识别目标、已有素材可用条件、新拍时机、质量判断、重拍边界 |
| 位置数据 | 当前/指定/历史、精度与新鲜度理由、单次/持续、无定位替代 |
| 权限 | 数据与能力、用途、范围、确认组件、拒绝和授权后重试 |
| 执行动作 | 只读/副作用、业务确认、完成凭据、取消/修改/重复保护 |
| 用户交互 | 追问/选择/确认/进度/结果采用的已有组件或规范；新增需求单列 |
| 任务切换 | 后台是否继续、原任务去向、恢复、多个候选或任务的指代 |
| 等待与通知 | 真实进度、投递时效、实际送达后等答复期限、异步结果锚点 |
| 退出与设备事件 | 摘下、断连、离线、重连、用户结束后的各对象去向 |
| 表达 | 结果概述、展开/重复、数字读法、必要服务身份说明 |
| 依赖与例外 | 平台依赖、业务特殊策略、待确认项、推荐方案及理由 |
| 验证 | 规范/配置版本，文本、音色、设备、业务各层状态 |

## PRD正文
### 产品目标与场景
说明用户正在做什么、为什么用耳机、当前困难、服务价值、范围和成功标准。
### 完整产品流程
写从用户开口到结果获知的路径，解释主Agent承接、FA业务动作、感知采集、追问与确认。画用户能理解的流程图，避免只列技术状态。
### 详细交互
按真实场景写用户输入、系统判断、业务动作、用户听到的反馈、下一步及理由。包含普通完成、缺信息、拍照/定位不可用和业务特殊分支。
### 变更与恢复
在提交前、执行中、结果未知、已完成四个时点，说明更正、停播、取消、换话题和重试；无副作用查询可简化，但需说明适用性。
### 权限、边界与取舍
说明数据用途、获取方式、平台和硬件依赖、拒绝或能力缺失时的替代、为何选当前策略。
### 样例对话与验收
给真实自然口语样例及验收用例。每个关键分支有预期最终状态；覆盖是否适用，不能只贴通用用例。

## 附件
1. 配置卡、规则映射S01—S20及业务例外。
2. 事件表：用户/设备/FA事件→当前会话/任务/播放/采集状态→处理→新状态→用户反馈。
3. 用例：前置条件、输入与时序、预期交互、实际业务结果、证据方式、执行状态。
4. 依据与待决策项：每项业务和平台事实的来源，未确认分支的影响。

## 评审门槛
交互方案就绪：关键流程、解释、规则和预期完整；开发就绪：相关能力与业务决策明确；体验通过：实际音频和设备行为符合预期；业务通过：真实最终结果符合目标。分开记录。
