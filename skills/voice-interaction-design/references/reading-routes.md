# 交互规则按需读取路由

本页只改变阅读组织，不改变正文模板、两图、交互交付、统一Query正本或关键规则验收要求。下文的“§”指目标文件的章节编号。规则正文保留在原文件，以原文件为准。

## 1. 公共最小必读

每次调用先读 SKILL.md、调用方同版交接包，再读以下内容。按章节读取即可，不要求为寻找一条规则串联全文。

| 文件 | 公共必读部分 | 用途 |
|---|---|---|
| [交付模板](prd-output-contract.md) | 全文 | 固定交付与成熟度；其中专项要求按适用条件展开 |
| [生成规则](prd-generation-rules.md) | 一、二、四、五、六 | 从已定需求到节点、话术、走查与成熟度 |
| [可执行性规则](execution-readiness.md) | §1、3、5、6、18 | 证据到决定、中间态出口、确定用例、展开表和例外优先级 |
| [一致性与指标合同](consistency-and-metrics.md) | §1、3；生成后执行§2中的修复与退出门槛 | 唯一规则账本、同版修复、指标口径 |
| [语音体验补充](voice-experience-extensions.md) | §4—5 | 状态、权限、PA/FA承接、分层证据 |

公共安全底线不得由路由裁剪：只使用确认的原子能力与PA能力；查询意图不得转成写入；对外动作授权绑定当前对象、关键条件与有效期；用户实际听到决策内容后才接受授权；条件变更或过期使相关授权失效；未知结果保留原操作并核对，停止重复提交；音频停止和业务取消分开；成功表达须有对应业务证据；用户续接经过PA；未确认的硬件、通知、记忆等能力保留待核实。无响应计时从实际投递并可作答之后起算，缺回执用明确停止/退出路径。

上述底线即使本次没有交易也要检查适用性。比如纯查询仍可能泄露敏感内容、错误表达成功或把候选选择误作授权。

## 2. 按任务和风险追加

先从冻结功能、前置条件、外部动作、状态与事件识别触发项，再取各行的并集。一个业务可以命中多行；业务名称不是免读依据。下表的执行规则均指 [execution-readiness.md](execution-readiness.md)。

| 触发项 | 追加读取 | 交付检查 |
|---|---|---|
| 收集、搜索、候选、消歧 | 生成规则配方A、C；执行规则§11、13、19 | 保留查询/写入意图；每问有实际修复与返回节点；当前信息有确定证据 |
| 提交、支付、取消、其他对外副作用 | 配方B、D、E；执行规则§2、8、9、11—14、16 | 当前对象与条款授权、提交边界、未知结果核对、迟到成功、动作各自的结果 |
| 完整业务或提交后的履约 | [生命周期闭环](lifecycle-completeness.md)全文 | 能力范围内的阶段与完成证据；业务和履约分轴；缺口进附录 |
| 多轮补问、沉默、含糊、问话播放/计时 | 一致性合同§2；执行规则§13—14、19；语音补充§1—2 | 非零播放时长算例、投递起点缺失、迟到计时器、逐问错误矩阵 |
| 打断、变更、旁插、暂停、恢复、停止 | 配方D；执行规则§4、12、16—17；语音补充§1—2 | 暂停来源与作用域、停止失败、旧输出失效、恢复资格与资源去向 |
| 事实、报价、授权、素材或动作有期限 | 执行规则§2、8、12—14、16 | 分开各期限；跨阶段与跨提交截止；过期后的具体行为 |
| 已提交对象更正、持久记录 | 执行规则§7、13 | 字段×状态矩阵、字段副作用、可更正范围 |
| 共用门禁、共用修复、多个动作共享节点 | 执行规则§9、11—14、18—19 | caller返回合同、逐动作结果、例外优先级、逐问错误矩阵与覆盖账本 |
| 预约、周期、改期、到点执行 | 执行规则§10—13、16；配方E | 发生项/代次、相对时间锚点、到点前提和无回执总截止 |
| 持续服务、后台规则、顺序或集合变化 | 配方E—G中适用部分；执行规则§11—13、15—18 | 请求与策略授权分开；无人在线异常、集合变化与持续前提 |
| 定位、拍照、媒体、传感或多源输入 | 配方F；执行规则§8、16；[扩展机制](future-interactions.md)中对应类型 | 平台证据、素材质量/时效、媒体返回与明确失败闭环 |
| 开放式互动、故事、教学、娱乐 | 配方G；扩展机制中对应类型 | 叙述与决策、重听与推进、结束条件 |
| 主动通知、敏感内容 | 语音补充§3—4；执行规则§14 | 通知生命周期；候选、查询和每句结果同一呈现权限 |
| PA/FA协作、任务切换、跨设备 | [子Agent规范](subagent-standard.md)相关章节；语音补充§4 | 基线架构、上下文/结果合同；依赖不可假定 |
| 播放、轮次、打断、延迟或设备验收 | [运行时证据](voice-runtime-evidence.md)全文；语音补充§5 | 模拟、服务、播放回执、音频、设备、性能分别给证据 |

执行规则§1—19均有入口。§18始终必读；§19在动态证据或逐问修复适用时必读。其他专项参考只有明确出现对应机制才读；[产品配置](product-profile.md)、[耳机规则](wearable.md)不得用来默认补充平台能力。新领域研究由上游提供；交互专家只补交互疑点，不重复发散业务范围。

## 3. 读取记录与交付门禁

在工作区或附录记录本次 `feature_ids、触发项、选读文件/章节、采用规则、排除理由、待核实能力`。这是AI交接材料，不给正文增加章节。变更时从受影响的功能、规则、节点、图边和用例重新选读；影响扩大就补读，不能复用过期的“不适用”。

交付前检查：每个适用触发项有已读依据；关键规则关联同版节点、两图与Query用例；公共底线无缺口；上游业务预期保持一致；未读章节不宣称已核验。事实、接口或PA合同缺失时记录阻塞及当前可用退路；设计检查通过、运行未测和实际失败分别报告。输出仍使用调用方确定的正文模板及交付形式。
