# 耳机／可穿戴无屏语音交互规范 V0.1

适用依据：用户已确认第一阶段服务耳机／可穿戴设备，以无屏语音为主。与通用规范V0.1组合使用；设备与业务能力以产品配置V0.2为准。以下为目标体验与设计规则，尚无真实设备测试。

## 体验原则
用户应在不看屏幕、少记信息的情况下完成常用任务，能随时停止播报、纠正和退出。设计时先保证简短语音闭环，再提供实际可用的屏幕或触控补充。以提示是否有用决定是否发声，避免每个内部状态都播报。

## 1. 无屏完成与信息节奏
每轮给出当前最有用的信息，复杂结果先概述，再允许“继续”“重复刚才的时间”“说慢一点”。用户说“第二个”时必须能从当前候选中定位；候选变化后重新建立指代。长列表分批提供，并说明还可以继续，具体批量取决于信息复杂度及试听结果。

时间、金额、对象等重要信息在结果中可理解；长标识按用户需求分段或用真实可用的其他通道承接。若某任务确实依赖屏幕，明确原因及入口，并将其标为需要屏幕的辅助路径。

## 2. 入口与低负担反馈
入口可能是唤醒词、按键、触控或系统事件，当前机制待确认。每个入口设计：用户如何知道开始收听、失败如何发现、如何退出。提示音可表达简单状态，复杂歧义用简短语音。用户已明确给出请求且系统即将反馈时，不必再机械播报“我在听”。

连续沉默时区分未听见、暂时思考和环境干扰；依据可用信号与测试决定等待策略。连续失败改变提示，提供重说或已支持的替代输入；退出后不反复重新唤醒。

## 3. 打断与任务控制
“嗯”可能表示继续；“等等”先停止当前播报，再按上下文判断用户是否要修改任务；“取消刚才那个提醒”指向业务对象。接受有效打断后停止旧播放，保留已完成动作，后续根据实际已听内容衔接。用户打断时无需再播一长段“好的，我停止了”。

有音乐或通话时，先由产品策略确定助手进入优先级、音量变化及恢复时机。短时间连续请求不得导致音乐反复恢复又被打断。用户明确要求暂停的音乐，助手退出后保持用户选择。

## 4. 佩戴、摘下与断连
如有可靠摘下事件，建议暂停私人内容播报；在途任务按业务状态单独处理。重新戴上时不突然续读长段或私人内容，可在合适入口简短询问是否继续；低风险短反馈是否自动恢复由产品策略确定。

若无佩戴信号，这些自动行为列为能力缺口，不借提示词宣称支持。无论摘下还是断连，输出路由都需实测；敏感内容只在已授权的路由播放，禁止默认转到手机扬声器。单耳/双耳变化不重建或重复提交业务任务。

## 5. 移动、噪声与离线
行走、风噪、交通或他人讲话作为测试条件，不把所有声音当成用户命令；无法可靠识别时给简短修复路径。高注意力场景控制信息负担，避免要求用户记多项候选或必须看屏幕。

网络失败时明确可用范围，只有实际支持本地执行才宣称可用。已提交动作超时先核对结果；断网期间不默认排队重放有副作用的请求。重连后先核对旧操作，避免创建重复提醒。无法核实时保留未知状态并给出可用下一步。

## 附件：规则与验收
| ID | 触发 | 规则 | 验证预期 |
|---|---|---|---|
| H01 | 无屏主路径 | 关键结果和下一步可通过语音获得 | 不看屏完成选定核心任务 |
| H02 | 长结果或重复请求 | 分段、可继续、可重复关键项，候选指代稳定 | “第二个/重复时间”选对当前对象 |
| H03 | 进入与退出对话 | 反馈足以辨别收听/等待/结束，避免冗余发声 | 用户知道当前是否还需说话 |
| H04 | 附和/打断/取消 | 应用T01—T03并减少额外确认播报 | 标注音频分别验证，不误取消 |
| H05 | 音乐或通话并存 | 按已确定优先级协调，尊重用户主动暂停 | 无反复抢占，恢复符合策略 |
| H06 | 摘下/戴回/单耳变化 | 按可靠事件与恢复策略处理播放，保留业务状态 | 无突然泄露/重复操作；能力不支持则注明 |
| H07 | 路由变化或断连 | 私人内容保持授权路由 | 真机断连不意外外放 |
| H08 | 断网/重连 | 副作用请求不默认排队重放，核对未知结果 | 原请求成功后重连不重复创建 |
| H09 | 噪声或移动 | 修复路径简短、可退出，不凭噪声执行 | 误触发、漏检及退出分别统计 |

## 功能设计增加的输入与输出
输入补充：是否必须无屏完成、环境与隐私级别、音乐/通话并存、佩戴感知、路由和离线能力。
输出补充：无屏完成路径、反馈声音含义、暂停与恢复策略、设备事件对任务的影响。每项给出目标行为、所需能力和未支持时的处理方式。
