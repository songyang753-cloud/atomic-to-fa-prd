# 子Agent交互能力分类与组合规则 V0.1

## 适用目标
产品依托耳机提供大量子Agent服务，包括生活助理、打车、导航及后续业务。生活助理是首批样板，不是规范的业务边界。每个新功能按自身行为选择适用规则，无需为每个业务重复建立一套规范。

以下为目标交互设计。业务接口、服务协议、设备信号和性能需以实际接入核对；不构成现有能力或上线范围承诺。

用户提供的40条未来方向采用[专项交互规范](future-interactions.md)，逐条映射见[覆盖矩阵](direction-coverage.md)。本页八类是能力索引，专项补齐长期角色、多人共享状态、实时轮次和紧急触达等机制。

## 三层复用
第一层是所有子Agent共同遵守的规则：主子职责、上下文、追问、权限、停播、任务状态、取消、未知结果和无屏反馈，见子Agent交互规范。

第二层按能力组合专项规则。例如打车需要定位、选择、交易和异步状态；导航需要定位、持续引导和路线变更。一个FA可以组合多类，不能只按业务名称选一类。

第三层由具体业务PRD确定参数和策略：打车的车型、上车点、预估费与取消条件，导航的出行方式、路线及偏航处理。共用规则不代替服务商真实约束。

| 能力类型 | 常见功能 | PRD需补充的交互决策 |
|---|---|---|
| 信息查询与推荐 | 天气、地点、内容推荐 | 来源时效、排序理由、候选选择与继续查询 |
| 个人记录与安排 | 提醒、日程、待办 | 时间语义、对象修改、循环范围、完成与触达 |
| 感知与识别 | 拍照识物、翻译、环境理解 | 当前对象、素材批次、质量、重采及不确定性 |
| 位置与空间选择 | 附近搜索、上车点、目的地 | 当前/指定位置、精度新鲜度、同名地点和安全可达性 |
| 持续引导与监测 | 导航、运动、到站提醒 | 开始和结束、持续授权、事件优先级、失效与恢复 |
| 对外交易与履约 | 打车、订餐、预约、购物 | 明确提交边界、价格条件、对外数据、取消后果、履约状态 |
| 通信与共享 | 发消息、分享位置、邀请 | 接收方、内容复核、发送确认、送达与重复保护 |
| 媒体与设备控制 | 音乐、音量、拍摄控制 | 当前资源、控制对象、音频协调、停止和恢复 |

## 打车：从需求到履约的交互样板
用户目标：不用看屏也能选定正确上车点和目的地，理解关键费用条件后叫车，并持续获知必要状态。

流程：表达目的地→核对当前位置和上车点→消歧目的地→查询可用服务与报价→用短句说明关键选项及费用性质→确认具体叫车动作→提交订单→核对订单结果→等待接单和接驾→按实际状态提示→行程结束按服务能力查询结果。

“帮我看看打车多少钱”是查询；“就叫这辆”在当前选项和有效报价明确时才进入下单确认策略。确认内容至少覆盖上车点、目的地、所选服务及影响决策的费用条件。预估价与固定价按真实服务标明；报价失效或关键条件改变时，重新评估确认，不能沿用过时同意。

定位点不是天然正确的上车点。停车场、商场多门、道路两侧等情况需要可理解的地标或门口选择；无法可靠判断时向用户澄清，不假装知道用户所在出口。

下单成功、司机接单、司机到达、行程开始分别反馈。提交超时先查原订单，避免重复叫车。用户说“不去了”时判断当前订单及取消规则；有取消费或其他重要后果时按实际条件说明和确认，权威结果到达后才说已取消。

服务不支持、无人接单或叫车失败时解释状态及可选下一步，换服务或再次叫车由用户决定。定位共享、联系电话、付款和司机联系能力分别按授权设计。结束对话保留实际订单，停播不取消叫车。

## 导航：持续任务中的交互样板
用户目标：明确目的地和出行方式后，通过耳机持续获得可执行的路线引导，并能自然查询、调整或结束。

流程：目的地消歧→确认必要出行方式与起点→获取路线→概述关键路线、距离或预计时长及其依据→按明确意图和业务策略开始导航→按实时状态持续引导→偏航或路线条件变化时处理→到达或用户结束后停止导航任务。

搜索路线与开始导航分别表达；只有持续导航真正生效后才说“开始导航”。转向提示的提前量、方向表达、重复频率与定位要求需按步行/骑行/驾车分别验证，不在通用规范中固定秒数和米数。

位置失效时说明当前限制并采用业务批准策略；恢复后先核对当前位置和路线，不能继续播报旧转向。“换条路”依最新路线和用户偏好判断；目的地改变后旧路线提示失效。临时查询“还有多久”后是否继续引导取决于当前导航状态，查询本身不结束任务。

“别说了”先处理当前播报；“暂停导航播报”和“结束导航”分别定义，暂停时明确任务与定位是否继续。用户通话、摘下耳机或换话题时，按OS音频与触达规则承接，关键提示优先级需经产品和设备验证，不能默认打断所有内容。

## 多任务并行
打车等待期间可查询天气或设置提醒；导航期间可发起其他请求。每个PRD说明原任务是否继续、哪些事件需要提示及有效期，具体触达由OS编排。接驾通知、转向指令、私人提醒可能竞争同一耳机通道，需平台统一仲裁；FA不能各自抢播。接入能力未支持并发时，明确限制和用户选择，不承诺自动并行。

## 新功能接入方法
1. 写用户目标、业务对象与成功凭据，映射MA、FA及OS职责。
2. 从上表选择全部适用能力，明确每项业务差异。
3. 列主流程、关键选择与提交边界，给真实口语对话。
4. 分别推演未提交、在途、未知、已完成；持续任务另推演暂停、失效和结束。
5. 为主流程、异常与跨任务事件配置验收，标注实际验证状态。
