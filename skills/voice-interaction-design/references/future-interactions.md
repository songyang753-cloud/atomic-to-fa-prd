# 通用语音交互的扩展机制 V0.2

## 目标与依据
统一规范需支持生活助理、出行以及感知、陪伴、创作、游戏和协作。本文依据用户提供的用户提供的项目基线，2026-10-28官方CLI完整读取版本1390，共40条方向，另保留打车下单、导航和生活助理范围。

这些是设计覆盖范围，不是发布承诺。源表的可满足性与优先级按来源记录保留；本次未重新评估模型、硬件或接口，也不将源表评价升级为能力验证。

使用顺序：通用子Agent规范→能力分类与本专项规则→具体业务PRD→文本、音频、设备和真实业务分别验收。新增功能按交互行为组合规则，不能因名称相似合并不同产品目标。

这些扩展按交互机制选用，列出的业务仅作例子。新需求无须出现在任何方向清单中。

## 九类扩展机制
### X01 持续感知、自动触发与记录
适用路况、人物位置、困倦检测、高光记录及手势触发。用户需知道何时开启、正在观察什么、持续多久、如何暂停/结束；检测开启、事件命中、用户提示和素材保存分别呈现真实状态。

PRD需定义目标对象、传感器视角与覆盖、采样/连续方式、触发依据、连续确认、重复抑制、冷却、误触撤销和失效反馈。参数由场景测试决定。镜头看不到本人时不能承诺识别闭眼；识别到老师离开画面也不能直接推断其正向用户靠近。

高光需分别说明循环缓存、事件前后片段、筛选、保存与删除；用户说“刚才那段留一下”需核对实际缓存覆盖。缓存中断、无录像和剪辑失败都不能回复已保存。自动触发带副作用动作须有预先约定的授权边界，映射变化后重新确认。

持续行走辅助需单独验收提示时效、漏报、误报、视野与失效告知，允许用户区分主动场景描述和连续预警。目标可靠性和使用边界在专项PRD中明确；尚未验证时将体验限定为已具备的描述能力。

### X02 实时翻译、教学与现场提示
适用英语学习、方言翻译、社交提示、游戏建议。PRD先明确在听谁、对谁输出、是翻译原话还是给用户建议；多人说话需说话人或轮次依据，无法区分则澄清或短暂停止输出。

助手需让出真实对话的发言机会。按内容时效决定插入、等空隙、取消旧建议；过时建议不排队连播。翻译需保留原意和不确定片段；识别失败不补写成确定原话。方言理解覆盖与目标方言合成分别验证，支持其中一项时准确说明可用方式。

学习模式由用户选即时纠错、说完再评或练习后总结，避免每句话都打断表达。词汇/语法纠错、发音评分分别依能力提供。用户可暂停教学只聊天，或退出现场提示而结束持续收音；具体收音范围按授权处理。

### X03 角色陪伴、模拟通话与长期记忆
适用恋爱、朋友、熟人/逝者风格、IDOL角色和鼓励陪伴。建立角色时明确是模拟体验；剧情、用户提供的真实资料和模型生成内容分别管理。不能把生成的共同经历写成用户真实历史。

用户设定人设、可用音色和互动风格，提供自然退出/切换入口。退出角色后主Agent恢复正常服务，不让角色设定阻塞取消、权限或其他业务。指定音色需实际资源依据，声音切换失败时按已批准替代策略反馈。

模拟通话、真实电话、位置共享、求助发送是独立能力。只能模拟对话时，不能反馈已拨通联系人或已启动保护服务。长会话需定义断网、静默、通话插入、记忆保存和恢复。

长期偏好或事实写入需明确来源、保存范围、纠错和删除路径；有多人资料时按人物归属隔离。逝者资料引用与生成对白可被区分，用户可停止引用某段资料或清除角色记忆。

### X04 游戏、互动叙事与持久进度
适用海龟汤、牌棋/游戏建议、有声书、单人实景剧情。剧情/题底/规则与当前进度有权威状态，台词生成不能随意改写固定答案。每次选择绑定当前节点，过期输入不推进新节点。

区分用户与角色对话、对系统提要求及环境事件。问“你刚才说什么”重复内容而不重复扣资源、计分或推进剧情。打断后从实际已播和已提交选择恢复；“重来”明确重置节点还是整局。

局势来源不完整、画面过旧或规则不明确时追问；建议和实际执行分开。现实环境触发剧情需有有效感知证据，不能靠生成叙述声称现场发生事件。多音色、BGM、提示和真实导航竞争音频时经OS统一编排。

### X05 多人协作、审批与跨账号控制
适用朋友审批、手势控制朋友设备、多人实景剧本杀。先明确参与人身份、加入/退出、授权对象、可见范围和谁能操作哪个设备。私人角色线索定向发送，共享状态与个人秘密分别维护。

多人审批明确全员/部分同意规则、成员变化、拒绝、超时、撤回及过期回答。审批必须绑定具体商品/金额/动作版本，关键参数改变后旧同意失效。朋友收到消息、同意以及支付端允许执行分别记录；缺付款拦截能力时只提供提醒或建议，不承诺强制阻止支付。

跨账号指令须有接收设备有效授权及结果回执；手势识别成功仅证明输入命中。多人游戏需处理并发选择、冲突、断线重入和私密消息错投，不能用FA互调绕过平台分发边界。

### X06 外部事件、手机电脑与设备控制
适用刷视频、IDE待确认提示、音效/音乐控制。每条指令绑定设备、应用和当前资源；“下一条”须根据有效上下文指向视频、歌曲或候选列表。无目标设备状态时先核对。

识别口令、命令受理、目标应用执行分别区分。应用不在前台、权限失效或远端离线时不盲目重发。当前控制上下文过期后输入重新解释。自动恢复音乐尊重用户期间最新的暂停/切歌动作。

IDE真实待确认事件要关联任务、去重并在事件失效时撤销提示。提醒用户回电脑确认与语音代点确认分别授权；“可以”必须绑定具体待确认事项，多个弹窗时先消歧。

### X07 多源资料、长任务创作与证据检索
适用订阅检查、聊天/事件检索、每日人生短剧、高光成片。先明确哪些资料已导入、来源授权和覆盖时间；部分来源失效时说明本次覆盖范围。导入完成、索引完成、内容生成、导出保存和分享分别有状态。

引用聊天或历史事实需可追溯到实际原文，概括与原话区分，找不到时说明缺口，不编造证据。订阅扣费预测注明数据依据和时效；实际退订或阻止扣费属于独立授权动作。

生成前明确输出形式、选材范围和必要偏好。用户可排除素材、纠正事实、修改生成稿。只改稿不重做原始采集；生成重试不重复分享。照片、视频、播客依实际可用输出通道交付，纯语音概述不充当成片保存成功。

### X08 紧急求助与高时效触达
适用紧急联系人通知和连续位置更新。专项PRD需定义紧急入口、误触处理、实际发送渠道、接收方、位置新鲜度、弱网策略和失败路径。确认步骤按紧急性设计并单独验证，不能套用普通交易的一律多轮确认。

触发识别→动作发起→渠道受理→送达→对方回应分别记状态；只有相应证据才使用对应说法。警方渠道未接通时不反馈已报警。位置不可得时按可用信息与已批准策略执行并说明限制，不静默伪造坐标。

发送后说“取消”需区分停止后续更新、撤销待发动作及已经送出的消息；已经送达的信息按真实可撤回能力处理。紧急事项可能与导航、通话、音乐竞争，平台需制定优先级、失败提示和实际链路测试；该规则不承诺通用耳机已具备紧急保障。

### X09 娱乐表达、估计与用户可控风格
适用运势、穿搭锐评、饮食调侃、犬类状态、选水果和盲盒建议。开场及必要节点用自然表达区分娱乐设定、主观建议、估算和可验证事实，避免每轮机械免责声明。

用户可选择调侃强度、关闭音效、调整目标并随时停止；已有偏好不能覆盖当前“别这样说”的明确要求。识别结果与推测分别表达：包装可见特征不能支撑确定盒内款式，犬叫情绪观察不能包装成可靠逐句翻译，食物热量需份量与估算范围。缺依据时缩小结论或追问。

健康训练目标、组数、计时和实际完成分别维护。倒计时依可信计时机制，暂停后明确剩余时间；完成由用户或有效传感器确认。BGM与倒数的混音、音量和恢复需设备验证，生成鼓励话术不能替代精确计时。

## 专项验收方法
每项专项规则至少生成正常、失效、纠正/退出及异步/并发用例，按实际适用性展开。下面是跨业务必须覆盖的设计预期，尚未执行：

| ID | 测试条件 | 预期 |
|---|---|---|
| FX01 | 持续采集中相机遮挡、断网或视角失效 | 识别失效可理解，不继续暗示观察可靠 |
| FX02 | 缓存不含用户要求的高光片段 | 反馈缺失，不虚报保存 |
| FX03 | 多人说话、翻译延迟、旧建议返回 | 对象清楚，过期输出取消，不抢真实对话 |
| FX04 | 用户退出角色并改问真实业务 | 主Agent正常承接，角色音色/记忆按策略处理 |
| FX05 | 故事中重复、打断、重来与过期选择 | 状态一致，无重复推进，重置范围清楚 |
| FX06 | 审批后金额变化、成员撤回或超时 | 旧同意按规则失效，无越权支付 |
| FX07 | 跨账号设备授权撤回或重复手势 | 拒绝无授权指令，防重复，结果可核对 |
| FX08 | 应用不在前台、IDE事件已结束 | 无误操作/旧提醒，确认绑定当前事项 |
| FX09 | 部分资料失败、检索无原文、导出失败 | 覆盖和状态准确，不生成虚假证据 |
| FX10 | 求助受理未送达、定位失败、用户取消 | 分阶段反馈，已发与待发处理准确 |
| FX11 | 关闭调侃/音效、估算信息不足 | 当前偏好生效，结论符合证据 |
| FX12 | 训练暂停、恢复、误说完成 | 计时/阶段正确，完成有依据 |

## 扩展与采用
源表每个方向的映射见[40条方向覆盖矩阵](direction-coverage.md)。映射表示已给出需要遵守的交互规则；每份业务PRD仍需填写参数、实际能力、失败策略和验收结果。后续新增方向先检查现有规则能否组合覆盖，出现新的交互机制时再扩规范。
