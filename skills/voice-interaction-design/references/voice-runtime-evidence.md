# 语音运行时证据附录

按需用于涉及轮次、打断、播放回执或性能验证的PRD；定义目标契约与测试证据，不要求FA自行实现平台检测器或重建状态机。

## 信号与决定的责任分离

| 信号 | 能支持什么 | 仍须哪个决定 |
|---|---|---|
| VAD语音活动 | 音频疑似语音区间 | 平台判断是否应让话，不能证明语义完成或授权 |
| 静音端点 | 当前配置下停顿达到端点条件 | 轮次管理结合上下文判断用户说完、思考或采集失败 |
| 语义轮次结束 | 模型估计本轮表达完成 | 平台结合短控制、修正与业务上下文决定是否接话 |
| STT最终转写 | 转写服务定稿文本 | 意图/业务层判断回答、附和、纠正与动作；定稿不是用户授权 |
| 接受打断事件 | 平台接受了让话请求 | IO提供实际停播状态，业务分别处理已提交副作用 |

需要哪些信号、谁提供、缺失如何降级写进依赖。沿用现有业务/呈现/采集三条状态轴，不另外创建一套相互冲突的控制器。

## 四种停止各自有证据

1. 生成：取消请求及晚到片段过滤，绑定任务/轮次/输出版本。
2. 播放：清队列并停止正在出声的内容；记录实际停止及已播范围。没有回执时说明只能确认停止请求已发出。
3. 对话历史：仅将实际呈现的条件当成已告知；保留用户未听部分，恢复前重新校验。
4. 业务副作用：原操作ID、提交/完成/未知及核对路径；停止音频不自动回滚业务。已完成时说明结果，后续撤销/修改沿用业务授权。

## 毫秒时间线与采集

每条关键竞态按同一时钟写 event_id、task_id、turn_id、operation_id（如有）、输出/输入版本、事件类型、发生时间、观测时间、来源、状态。跨设备记录时钟域及同步误差；不可比时仅报告因果顺序，不相减伪造时延。区分缺事件、未发生、未采集。

覆盖：用户输入、端点判断、最终转写、接受打断、取消生成、停止队列、实际停播、晚到输出丢弃、原操作结果、后续告知。用具体算例走查“用户纠正→旧音频迟到→原操作已完成”，分别断言播放、历史和业务结果，不能只看最终回复。

延迟采集保留原始事件记录、设备/模型/网络/配置、采样方法与样本数；记录端点、推理/工具、合成、传输/排队、实际播放各阶段。并行阶段按关键路径分析，不把重叠耗时相加。按照[指标合同](consistency-and-metrics.md)统计分位数及失败/缺失样本；缺设备回执时止于已观测阶段。仅获准采集必要信息，原始音频/照片不作为默认日志附件。

本文为依据既有本机规则与Claude参考报告所作的产品适配。外部研究值未作为平台阈值引入；参考报告中的实测、标准条款须回查原始证据后采用。
