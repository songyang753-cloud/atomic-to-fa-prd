# 同版一致性、计时与指标合同

所有PRD生成时读取。以下为本产品设计方法，不是外部性能事实。详细表、事件记录放附件，正文保留影响用户的行为与决定。

## 1. 先建唯一规则账本，再生成与核对

从本次业务选择适用机制，为每条共享决定建立唯一规则键：适用节点、触发事实、参数及单位、起止事件、优先级、下一状态、资源动作、验证用例。正文、节点、对话、状态表、验收使用同一决定。原有规则ID保留；不用为无关机制增加表格。

生成结束必须做语义交叉检查，交付附件记录实际发现与修正：
- 从每条关键规则追到全部适用节点、至少一个具体用例；从每条用例反查节点和规则。适用但没覆盖的分支列缺口，不能用“已覆盖”代替检查。
- 比较相同参数、计数、超时起点、版本、授权条件和资源归属在五处是否一致：流程、状态、话术、对话、测试。面向用户的口语数值也须换算核对：如“半分钟”只能对应30秒，不能代表36秒；涉及资源停止或承诺期限时使用准确数值，禁止用未定义的近似表达代替。
- 每个非终态代入一次用户输入、沉默和外部迟到事件；验证暂停、结束、失效版本抢占正常结果。
- 对含时间或金额的示例做数值代入；用明确事件序列证明预期。发现生成内容矛盾先修正再交付；反复出现则记录共性规则修订建议；仅在用户已授权修改 skill 时回补通用规则后重新生成，普通 PRD 生成任务先修复本项目交付并报告建议。区分文字检查、局部模拟、设备实测。

## 2. 多轮等待按实际事件重新起算

第 i 轮问题的无输入计时起点 a_i = max(该轮实际播放完成 p_i, 该轮收听可用 l_i)，截止 d_i = a_i + W_i。每次补问另有播放时长；不能从首轮播完直接写 W、2W、3W 的绝对时点。无播放完成或收听就绪证据时，不推断用户已经获得完整作答窗口；给阻塞或可验证的替代策略。

收到属于当前轮的有效输入即取消该轮无输入计时；句内停顿、暂缓、权限弹出、输出被打断和断连另按其状态处理。提示被打断时说明继续接收回答还是重发问题；旧轮超时回调使用任务/轮次/版本校验后失效。收听在等待中失效时停止无输入判定，转采集修复；恢复后重问或明确告知并给足新的窗口。回答与超时同刻时，使用输入起始事件与截止事件的可比时序，截止时刻已开始的有效回答优先；缺少时序证据时保留输入澄清，不能直接执行有后果动作。

验收至少给一条包含非零补问时长和非零收听延迟的具体时间线，逐轮列 p_i、l_i、a_i、W_i、d_i，外加截止边缘回答和旧计时器迟到。每轮测试必须引用自己的起点；时间线统一声明零点，每个测试时点标明绝对时间t或轮内偏移Δ，并给换算（如a₂=17秒，Δ=11.99秒，t=28.99秒），禁止只写“第二轮11.99秒”。独立资源保留上限与无输入窗口分开，写清起点、先到优先级与终止原因；所有示例数值标“设计算例”。例：首问 p=0,l=0,W=8,d=8；补问8秒开始、11秒播完、12秒收听可用，下一截止20秒；再补问20秒开始、24秒播完且可收听，下一截止32秒。此例只解释公式，不要求业务采用8秒或两次补问。

### 生成后修复与退出门槛

完整初稿不是交付终点。先逐项检查本轮已知回归条件，再交叉检查相同决定的所有引用；每个发现记录规则位置、受影响节点、修复及复查结果。文档层可自行决定的问题在生成阶段收敛，不能作为“待平台确认”转移。能力确实未知时写完整的有能力／缺能力路径与当前阻塞，文档因此仍可完整。口语数值须与资源上限精确一致，时间例须声明统一零点；同时代入补问播放、收听延迟与更短资源上限，区分何种原因先结束。重复生成仍出现相同问题时，记录规则缺陷及受影响范围；用户已授权修改 skill 时补强通用规则后重新运行，未授权时修复本项目交付并提交通用修订建议。生成与生成后按Skill修复均保留输入和版本；输出整份同版稿而非补丁拼接说明。

## 3. 指标合同：先口径、再目标、最后实测

每项适用指标给唯一键、用途、起止事件/分子分母、单位、样本与排除项、分组、目标、目标来源与状态、责任角色、实际结果及证据。来源状态区分：平台已定目标、业务设计假设、外部参考锚点、当前实测。没有证据的值不得称行业标准或实测；不因采用串级或端到端架构直接推导达标。

分别定义用户实际说完→设备首个可感知反馈、→首段实质答复；填充语单列。打断分别记录输入出现/被接受→设备实际停播，说明采用哪个起点。用户说完的人工标注与平台端点决定也分别保留。无设备播放证据只报已观察到的服务事件，不以生成首包代替听到。量化目标可待平台确认，须列责任方与验证计划。

业务完成保留失败、放弃、未知，并明确各自分母；路由precision/recall给标签、样本与分母，不能充当关键语义正确率或任务完成率。若来自atomic-to-fa-prd交接，保留交接目标并注明其“模板建议目标”性质；业务有不同目标时单列差异待决，不静默改交接合同。

数值复用时保留来源日期、适用模型/设备/网络/配置、样本量、证据路径和采纳前复核状态。小样本只支持本次条件，不外推所有模型。未核对原始资料的标准条款或外部毫秒值不作强制阈值。

## 4. 新业务验证

回归案例用于查修复，另选尚未用于本轮改规则的业务输入，冻结Skill后独立生成；只给业务需求和真实能力依据，不给预期答案或历史案例。声明所测新机制和仍未覆盖的机制。对生成稿用具体反例核对、发现共性问题先记录规则修订建议；用户已授权修改 skill 时先改规则再生成，否则修复本项目输出并单列建议。新案例被用于改Skill后作为回归案例保留；后续新一轮盲测应另选业务。报告记录输入、Skill版本/哈希、原始生成稿、检查及未测层级，不能以文件齐全判定行为通过。
