# 通用功能输入与输出模板 V0.1

子Agent PRD优先使用[专用配置卡与PRD模板](subagent-template.md)；本模板用于单个通用功能或局部交互。

## 输入
- 功能名及用户目标：
- 真实典型场景、设备和环境：
- 参数：必填/可选、来源、有效性、默认值依据：
- 业务动作、成功证据、失败返回、结果查询方式：
- 权限、确认、风险、可修改/取消范围：
- 无屏完成要求、环境与隐私、音频并存、佩戴/路由/离线能力（适用时）：
- 依赖的产品配置版本：
- 已确认事实和依据：
- 暂用假设、待决策项：

没有的信息填“待确认”，不补造默认值。引用已有需求可用原文及位置，避免用户重复填写。

## 输出正文
### 1. 场景与目标
用户当时要做什么、成功是什么、适用范围；列清事实和设计假设。
### 2. 交互流程
入口→主要步骤→结果；说明为何需要追问或确认。异常路径及退出去向。可用简洁流程图，状态详表放附件。
### 3. 样例对话
正常、缺信息、歧义、纠正、打断、失败等适用情形。业务动作写在括号中，避免把示例误作实际运行记录。
### 4. 状态与反馈
说明收听、等待、执行、结果反馈和结束；被打断或切换后如何续接。
### 5. 依赖与待决策项
目标行为需要哪些能力、可用替代方案、缺口影响哪个分支。待决策项给建议和理由，关键分支保持待定。
### 6. 验收用例
给用户可理解的成功/失败判定。实测结果按层级单列，设计预期保持明确。

## 输出附件
- 版本：规范、模式库、产品配置、功能方案。
- 模式与规则映射：流程节点→适用模式→规则ID→例外理由。
- 状态表：事件→会话状态/任务状态/播放状态→动作→下一步。
- 用例表：ID、前置条件、输入/事件、预期反馈、业务最终状态、适用规则、验证方式、实际结果。
- 评审问题：严重性、具体位置、用户影响、依据、修订、复核结果。

## 验证标签
设计预期 / 人工文本走查 / 音色试听 / 设备音频验证 / 真实业务验证分别记录“通过、失败、未测、受阻、不适用”。未测不并入通过数；受阻写明缺什么；不适用写理由。不要用一个总分掩盖阻塞项。
