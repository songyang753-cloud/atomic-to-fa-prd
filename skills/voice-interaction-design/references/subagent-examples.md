# 子Agent交互样例与验收矩阵 V0.1

用途：验证规范可以支撑不同子Agent PRD的交互章节。以下为设计样例，服务、接口及运行结果均待确认；不是三份已经完成业务定义的完整PRD。依子Agent规范V0.1、产品配置V0.3。

## 样例一：拍照识物FA
### 场景与目标
用户通过耳机询问眼前物体，希望免手持手机得到简短解释。成功：回答基于当前目标的可用素材，说明必要不确定性；拍摄及分析过程对用户可理解。

### 交互流程与理由
主Agent理解“帮我看看这是什么”→确定当前目标→判断现有素材能否适用→需要新拍时由OS对应路径采集→获准数据交由识物FA分析→FA返回结论和不确定性→主Agent组织短答，交互编排呈现。

选用P01查询、P03补充、P05等待、P08恢复；新拍严格S07—S09。FA获取原始图片须有平台许可，硬件能拍照本身不证明FA可读原图。

### 样例对话
用户：“看看这是什么植物。”
系统：（目标需新照片，权限满足后，在采集前后按联调时序告知）“我拍一下看看，请把镜头朝向植物。”
系统：（采集可用，识别返回后）“看起来像绿萝。需要我介绍怎么养吗？”
若画面模糊：“这张没拍清，请靠近一点再拍。”重拍是否自动触发按已授权策略；用户可说“不看了”退出。
若用户换目标：“不，是旁边那个。”先对齐目标并新采；旧图结果迟到不再作为当前回答。
若新采失败：“这次没拍成。”提供可用的重拍或文字描述路径，不能改用旧图装作识别成功。

### 特殊边界
无法可靠识别时说出限制；识别结果不扩成食用安全或医疗保证。无原图权限时按平台授权失败流程回报，授权后用户重试；不在原task内假定自动继续。

## 样例二：附近地点搜索FA
### 场景与目标
用户走路时想找附近咖啡店。成功：候选与用户本次指定或有效当前位置匹配，用户能不看屏理解并选定；是否导航由后续明确意图决定。

### 交互流程与理由
用户“附近有咖啡店吗”→主Agent检查位置来源及有效性→需要时获取新定位→地点FA按获准的位置输入检索→返回可比较候选→主Agent分批读出概述→用户选择或追问。

候选播报含名称与有依据的距离/方向或区别点。精确步行时间只有路线能力和对应数据支持时才提供。“第二个”仅引用当前候选，不跨FA或历史列表猜测。点击/手势选择仅在实际有该能力时加入。

### 样例对话
用户：“附近有咖啡店吗？”
系统：（位置满足要求，查询完成）“找到几家。第一家是A，距离约……；第二家是B，距离约……。你想听哪家的详情？”
距离为结果数据槽位，不是实际查询结果。
用户：“第二家营业吗？”
系统：（续接原候选，查询营业信息并保留来源限制）“……”
用户：“查杭州的，不是我这边。”
系统：更新地点，必要时问商圈；新目标不再使用原附近候选。
定位失败：“暂时没取到当前位置，你可以告诉我附近地标。”用户补充地点后作为新的明确输入查询。

### 特殊边界
单次检索不持续跟踪。商家营业状态注明信息时效限制。导航、预订和支付需各自业务范围与确认规则，搜索成功不自动执行。

## 样例三：到站提醒FA
### 场景与目标
用户说“到人民广场站提醒我”，希望不持续查看屏幕。成功：目标站点及路线/方向足够明确，监测规则真实生效，命中后在有效时段按OS触达策略提醒；失效可被用户理解。

### 交互流程与理由
先消歧城市/站点和必要方向→说明持续位置监测用途并满足平台授权→注册已支持的监测规则→取得生效凭据→反馈提醒已开启→后续事件按回调锚点承接→FA提供提醒意图→OS决定触达。

“已开启”要求规则已生效，不使用“我记住了”掩盖注册结果未知。缺持续监测能力时说明限制，不能只靠一次GPS查询承诺到站提醒。基线中存在默认感知原料，并不自动证明该业务事件、阈值和离线命中已接通。

### 样例对话
用户：“到人民广场站提醒我。”
系统：（站名歧义时）“你说的是哪个城市的人民广场站？”
系统：（说明用途、获得必要授权且规则生效后）“已开启到站提醒，目的地是……。你可以说‘取消到站提醒’。”
若FA因缺授权失败，先说明所需授权，保留需求为待办；用户授权后“再试一次”按原需求重派，成功后才说开启。
用户：“取消到站提醒。”
系统：（规则停止成功）“已取消到站提醒。”停止失败或未知则说明还在核实，不继续承诺已关闭。

### 特殊边界
提前量、定位质量、路线匹配、弱网或地下无定位时策略都需业务和设备验证。首次PRD可提出推荐方案，但未联调前不能承诺“绝不错过”。摘下或通话时触达处理与时效必须明确，到站后过期不重播旧提醒。

## 共用验收矩阵
所有下表均为设计预期，未执行真实设备或服务测试。

| ID | 场景与时序 | 预期 | 依据/验证 |
|---|---|---|---|
| A01 | 正常业务完成 | 任务结果正确，用户听到有依据结论 | S01/S13；业务+音频 |
| A02 | FA普通追问，用户一次补多字段 | 保留已知，沿原task续接 | S03/S05；任务事件 |
| A03 | 追问尚未送达，等待较久 | 不当作用户沉默；按投递状态处理 | S06；投递/闭合回执 |
| A04 | 两个FA都有候选，用户说第二个 | 按当前明确上下文选择或先澄清 | S03；多轮用例 |
| A05 | 执行中换任务后再说继续 | 原任务可追踪，无重复执行；歧义澄清 | S04；事件顺序 |
| A06 | FA无能力或明确失败 | 说明限制，不自动换服务执行 | S20；对话+调用记录 |
| A07 | 缺权限导致FA失败 | 需求保留待办，授权后用户重试重派 | S12；权限与任务事件 |
| A08 | 附和、停播、纠正、取消 | 意图分开，任务与播放状态正确 | S15；标注音频+业务 |
| A09 | 副作用超时后重复请求 | 查询原动作，不重复提交 | S13/S16；最终对象数 |
| A10 | 旧FA结果在新任务中迟到 | 不串台、不自动恢复；副作用仍核对 | S17；任务和播放事件 |
| A11 | 摘下/断连/结束交流 | 无未授权外放，未完成对象有去向 | S18；真机+业务 |
| A12 | 无屏全流程、重复关键结果 | 可完成核心任务，指代和重复正确 | S14；用户任务测试 |
| V01 | 有历史照片但用户指眼前新物体 | 不直接使用不匹配旧图 | S07；素材引用 |
| V02 | 新拍失败但旧图识别已返回 | 明确本次失败，不冒用旧结果 | S09；批次事件 |
| V03 | 模糊、遮挡、多物体 | 给具体指导，重拍有界，可退出 | S08；图片+对话 |
| V04 | 重拍后旧图结果迟到 | 只回答当前对象与批次 | S09；素材和结果关联 |

| L02 | 定位陈旧、漂移或失败 | 核对/重新获取/地标补充，明示限制 | S09/S10；位置元信息 |
| L03 | 单次附近查询 | 不注册持续定位或监测 | S11；规则和权限记录 |
| T01 | 到站规则注册未知/失败 | 不说已开启，核对或结束 | S11/S13；注册回执 |
| T02 | 取消持续监测失败或未知 | 不说已关闭，解释实际状态 | S11/S15；规则状态 |
| T03 | 通话、摘下或到站事件过期 | 按时效和可用通道处理，不播过期旧提醒 | S17/S18；触达事件 |

## 当前结论
三个样例能在文档层覆盖视觉、单次定位、持续监测的不同交互需求；实际平台组件可用性、敏感数据授权、原始素材访问、采集与任务接口尚待核对。真实子Agent需求确定后，再分别形成完整PRD并运行对应验收。
