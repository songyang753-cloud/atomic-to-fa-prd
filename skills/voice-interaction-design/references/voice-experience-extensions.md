# 耳机语音体验补充规则

按需求选择以下章节，与生成规则合用。以下是本产品采用的设计规则；外部资料提供方法，具体平台接口和性能须验证。

## 1. 用户尚未说完，以及误打断后的恢复

适用于所有需要用户说话的任务。PRD写清可回答状态、等待结束条件和让话后的去向；检测阈值由平台验证，不直接填固定静音毫秒数。

| 情况 | 生成的交互行为 | 验收重点 |
|---|---|---|
| “明天……下午三点……不，四点”含停顿和自我纠正 | 合并本轮有效内容，最终时间为四点；若已经错误接话，让话接收后续纠正 | 不截断未完成表达，不根据中间识别片段提交动作 |
| “让我想想”“等一下” | 进入暂缓回答；告知可说“继续”恢复；写清保留期限及到期后的恢复入口 | 暂缓单独处理，不累计为识别失败；业务报价等仍按真实有效期失效 |
| 播报中说“嗯” | 结合当前问题判断附和或回答；有后果的授权不能仅凭孤立附和推定 | 叙述不意外跳段，确认不误提交 |
| 播报中短促说“停”“不” | 保留短指令有效性；先让话，再判断停止、否定或纠正对象 | 不以时长短、字数少过滤真正控制 |
| 咳嗽造成停播，已确认没有新意图 | 若原内容仍适用，从可理解的短句边界续播；必要时简短重述 | 依据实际已播位置恢复，不整段重播或跳过未听内容 |
| 停播后没有转写，原因不明 | 保持让话，最小澄清“你刚才想说什么？”；按当前无输入路径退出或恢复 | 空转写保留不确定性；未听清的纠正不能被当作无意图 |

续播前核对任务仍有效、用户未换目标、内容未过期。涉及已提交操作时，查询业务状态后续接。对话历史以实际送达用户的内容为依据；播报位置不可得时保守重述关键条件，不能假定用户听完。

## 2. 适应说话与收听方式

每份PRD沿用平台已确认的沟通设置；有特殊需求才展开差异。对连续数字、地址、拼写及自我纠正保留适当停顿；噪声、口音和慢说分别验证。只凭声音不推断身份、年龄、能力或授权。

“慢一点”作用于后续播报；“再说下金额”只重述该信息；“简单说”缩短解释并保留影响决定的条件。真实语速控制缺失时，明确采用较短分段和按需展开，作为目标能力的临时替代。用户延长回答时间时，写出如何恢复、停止等待和再次进入；不能永久占用收听或保留过期交易条件。

数字、专名、日期与单位按目标语言写可听清的读法，避免仅靠画面、符号或颜色区分。关键实体或否定词未听清时核对对应部分。例如“不用高速”中的否定关系须验证；整体识别准确率不能替代这项验收。实际TTS试听与文本朗读分别记录。

## 3. 主动通知的完整生命周期

适用于提醒、异步结果、行程变化、连续导航及主动建议。先区分用户已要求的本次结果、持续订阅、系统主动推荐，沿用既有授权；持续推送的范围和关闭方式须明确。

PRD逐类填写：触发事实及来源、关联任务、授权范围、时效、紧急程度、可否延后、打断规则、合并/去重、播报内容、需要的回应、未回应与关闭后的行为。普通通知如何排队、关键通知如何参与现有IO调度应明确，FA提交意图和时效，由平台统一呈现。

- 发生在用户说话中：默认排队；确需抢占的事件须由需求说明理由、平台支持及恢复原任务的方法。
- 延后播放：播前重新核对事实、版本与时效；失效即撤回或改为仍有用的状态摘要。已到路口的转向口令不能恢复后原样补播。
- 多次变化：合并同一对象的旧事件，保留最终有效状态；需要逐条保留的事件明确理由。
- “先别说”：停止本次播报并说明可否稍后获取；“以后别提醒这一类”：调整对应通知范围；两者各自保留业务任务的真实状态。
- 敏感结果：按用户隐私设置、真实输出渠道和必要性决定播报详细程度；必要时先说“有一条私人事项，要现在听吗？”佩戴耳机本身不作为身份认证。

敏感内容门禁同时覆盖用户主动查询、搜索/消歧候选、修改/删除确认、成功/失败复述、恢复摘要和日志展示，不只覆盖到时通知。逐类标出哪些字段能先读、哪些须当前身份/渠道/内容授权；无详情授权时使用日期、数量或不泄露内容的代号定位，用户能主动提供内容进行指代，不能为取得同意先读出受保护字段。隐私级别未指定时须确定当前保守策略和授权入口，完整对话与用例不可暗加未在初态声明的授权。

示例：车辆到达通知晚于订单取消才取得播放机会，应撤销旧到达通知；实际取消状态另按业务反馈。无通知接收回执时，记录已请求投递，用户已听到仍待确认。

主动通知若先问“是否展开”，再问“如何处理”，这是两个独立决定。分别给实际播完/收听就绪后的计时窗口、肯定/拒绝/含糊/重述/暂停/沉默出口与资源，首问重述不自动取得详情授权。明确各问允许的补问次数；详情后的处理窗口不能替代首问窗口。至少代入首问沉默、要求重述和暂停序列，同步正文与状态表。

## 4. 状态感知、权限与主子Agent承接

PRD区分收听、处理中、播报和麦克风关闭。提示应对应真实能力状态；收听不可用时说明原因与恢复入口。提示音/触觉须沿用平台实际支持，用户不能被提示成可说话却未被采集。停播、结束当前收听和关闭麦克风分别设计，并明确对持续采集的作用。

本产品按既有MA/IO/FA分工承接，不给每个FA新增唤醒词或独立音频控制。涉及任务续接或服务协作时，在附件写必要上下文：目标、已确认信息及有效期、权限范围、未解决问题、已提交操作标识与结果、实际已告知的信息、续接位置。只向有权且需要的接收方传递；原始录音、照片或位置按用途和权限提供。超出已有授权的新用途或接收范围，补充说明与所需许可，不对每次内部路由重复询问。

缺少承接接口时，把它列为依赖并生成实际可行的重新发起路径。只有收到可用的承接结果，才可告知进入后续办理；不能先承诺“已经接着办了”。不自行更换服务或重试对外动作。对用户只说明影响任务判断的变化，不播报内部路由细节。

## 5. 验收口径

适用时在PRD附件增加以下指标。每项给定义、分子/分母、采样条件、目标及其依据、实际结果与证据；尚无目标时给待验证的建议和责任人，不能填成实测。按语言、噪声及说话方式分组，保留样本量。

| 指标 | 口径示例 |
|---|---|
| 用户表达被过早截断 | 仍在表达却被系统接话的轮次 / 可判定的用户表达轮次 |
| 有效打断响应 | 成功让话的有效控制或纠正 / 标注为应让话的事件；另报响应时间 |
| 误打断 | 被错误停播的附和或非意图事件 / 已标注的附和或非意图事件 |
| 关键含义保留 | 对象、金额、日期、否定等关键含义正确的样本 / 含对应要素的可判定样本 |
| 回应延迟 | 分别量用户说完至首个真实可感知反馈、至实质答复；填充语单独标记 |
| 任务与修复效果 | 真实完成的任务 / 发起任务，并分别列失败、放弃、未知；另报追问轮数与纠正后成功情况 |

文本走查用于发现漏分支。带音频验证轮次、读法与打断；真实设备验证可感知状态；业务回执验证任务完成。跳过和未知单列，并明确纳入哪个分母。没有播放证据时不报告“已听到”延迟或实际续播位置。
