## 6. 产品效果与体验指标

默认以下五项。目标为建议值，未实测时明确标注；不编造行业标准、基线或实测结果。

| 指标 | 定义与统计口径 | 建议目标 |
|---|---|---|
| 意图识别准确率（Precision） | 每类意图正确识别次数 ÷ 系统识别为该意图的总次数；分意图统计并报告宏平均。PA 派发与 FA 业务意图分别统计。 | ≥95% |
| 意图识别召回率（Recall） | 每类意图正确识别次数 ÷ 用户实际表达该意图的总次数；覆盖口语、模糊表达与上下文续接，分意图及宏平均。 | ≥95% |
| 首词时延 | 用户本轮实际说话结束，到设备开始播放回复声音；包含轮次判断、PA／FA 协作、生成、传输及播放等待。 | P50≤1秒；P95＜1.5秒 |
| 有效答复时延 | 同一起点到设备开始播放有实质内容的答复；等待语不计。按业务任务类型分别统计 P50／P95。 | 按业务设定；缺实测依据时标为待标定 |
| 任务完成率 | 达到用户预期结果的任务数 ÷ 本期支持范围内已发起任务总数。按任务类型统计，主动放弃、外部失败等原因分别列出，保留在总分母中。 | ≥90% |

说明各任务的业务终点；已受理、处理中、待核实等按真实状态处理。未实际执行业务的链路没有实测完成率。准召评测包含负例及范围外意图，未定义／无样本类别标注而不按100%计。

## 附录：能力依据与待验证项

- 原子能力映射：具体 MCP 工具、CLI 命令或 API → 功能；输入条件、重要返回及限制按需写入。
- 验证摘要：来源和日期、文档支持、实际查询结果、尚未执行的写入链路；脱敏、最小化保留业务数据，凭据不入文档。
- 能力缺口、待核对假设、影响产品判断的依赖。能力缺口不能作为本期已具备功能。
- **研发与 AI 实现包**：已确认需求与版本、原子能力及真实字段契约、输入来源与有效期、任务状态和转换、PA／FA 上下文承接、确认绑定与失效、重复执行防护（适用时）、错误与恢复、平台依赖；只写有事实依据或明确标为建议／待验证的内容。
- **交互详细设计**：保留 voice-interaction-design 输出的逐步交互表（环节与触发、已知及判断、用户可感知反馈、可能回应、处理与下一步）、完整对话实例及具体交互验收用例表，关联同一 F 编号；示例数据标注为演示。统一 query 与测试用例集按 [用例规范](query-test-corpus.md)维护；交互验收引用相同 case ID，不另建平行正本，不新增正文验收章。
- **统一 query 与测试用例集**：飞书交付时单独建立飞书电子表格，附录放真实链接、版本、覆盖摘要及执行状态，完整用例由同版机器正本生成到表格，供测试、AI 和研发消费。表格保留 query、action 及上下文、结果、禁止行为、追溯和验证字段，发布后回读全部用例并核对同版需求、交互与两图。正文目录不变。本地回归只给待发布文件，不创建或更新远端表格，不填写虚构链接。
- **给研发 AI Agent 的接手说明**：先读同一版本正文和附件，遵循已确认范围；列实现入口、已验证事实、待验证项、业务结果断言与验证方式。关键未知项明确影响和所需确认，禁止用模拟结果当真实业务成功。无既有代码时不编造代码路径。
- 大量接口字段、状态、追溯与证据放此处。无需另加上线安排、发布条件、目标用户分析、独立使用条件章或评审章。

## 作图与交付要求（作者执行，不进入正文）

正文保留固定模板结构。功能清单只收录能由用户原子能力与指定 PA 基线支撑的功能，能力依据简写；详细映射和验证状态放附录。删除清单前泛泛的“已查哪些、来自产品推演、用户价值仍待验证”等过程总述；只有影响用户使用和决策的具体限制保留正文，并直接说明产品如何处理。

调用 lark-doc 与 lark-whiteboard 及其要求的作图 skill。使用清晰层级、少量配色、统一节点和字号、短节点文案、清楚的分支标签；主路径突出，尽量减少交叉线。复杂图按阶段分组，避免字体缩小和整图过高。必须导出实际飞书预览检查裁切、重叠和可读性，再核对原始节点：核心节点、文字、连线均须可编辑；SVG、PNG、截图和本地图源不能单独满足交付要求。复用图的结构与设计语言，不复制瑞幸内容或原画板 token。

## 模板来源与版本（作者参考）

本仓库固定采用已确认的六章正文结构，统一使用 PA／FA、四列需求功能清单，首词时延 P95＜1.5秒。历史业务范例只作为方法参考；功能数量、优先级、自提范围与能力基线须按当前项目重新核实。
