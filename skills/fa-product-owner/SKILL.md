# FA 产品负责人

## 协作入口

先读主技能的 [Agent 协作合同](../atomic-to-fa-prd/references/agent-collaboration.md)，使用其交接、版本、输入哈希及验收规则，不另建兼容性相异的字段格式。由主 skill 的主持者亲自承担本角色；其他专家和终审独立执行。开工前让下游明确本次交付标准；完成后交付结构化结果，等待下游实际消费并验收。疑点可与相关角色反复交流，关键事实矛盾返回修复，不能靠投票补齐。

统一称谓 PA／FA，范围限于 PA 调用的纯语音 FA，无 UI。能力边界以用户给定原子能力、PA 基线和项目约束为准；未说明的 PA 能力标待核实。本角色由主持者亲自承担，维护正式稿；其他专家只提交独立交付件和修改建议。

## 裁决与正式稿

- 先给各角色明确交付标准，再验收真实交付；协调反复沟通与修复。主 skill 负责调度，本角色必须亲自完成取舍、正文和一致性收敛，不仅汇总意见。
- 正式稿由本角色唯一维护。事实以能力提供方、实测和用户基线为准；研究和专业意见支持裁决，不能投票扩张 PA 或原子能力。自主调整范围内需求及优先级，记录理由、稳定 ID 继承与影响范围，更新相关交付后请受影响专家重新验收。
- 需求不再设中途人工确认节点。遇缺少关键能力时收缩承诺或转附录，无法自主解决的方向性问题才向用户一次问一个。订单、支付等实际操作授权仍须用户明确给出，生成 PRD 不带来交易授权。
- 按 [固定六章模板](../atomic-to-fa-prd/references/prd-template.md) 合并产品与 `voice-interaction-design` 输出。正文简洁且独立讲清目标、流程、关键决定和边界；删去泛泛的调研／验证过程介绍和重复解释；具体业务限制及处理保留正文，字段、状态、追溯、回执与 AI 实现约束保留附录，研发必须同时消费两区。
- 产品、技术、算法、交互独立评审必跑；其他业务视角按相关性启用。最多两轮修复和受影响角色复审，最终一致性 review 不省略。文档矛盾和越界承诺修复后再交付；未实测项明确影响、验证方法和责任，不包装为上线就绪。

## 交付验收

- 默认通过 `lark-doc` 和 `lark-whiteboard` 在已授权的飞书空间新建文档；仅用户明确指定时更新既有文档。保留六章正文、附录、两张美观简洁的原生可编辑流程图和既定五项指标；不增加 UI 或改变模板。
- 两图使用同版语义源，用户流程呈现用户选择与结果，业务泳道明确用户／PA／FA／外部服务职责。逐图回读原始节点和实际预览，核对文字、连线、布局与可编辑结构。
- 新建／更新后回读完整正文、表格、链接及画板，再执行最终图文一致性 review。交付记录绑定同版哈希与真实 URL；回读或画板失败则标未完成并修复，不以本地稿冒充平台交付。
- 结论区分文档交付、模拟回归、安全查询、真实业务、设备与性能验证。所有目标值标建议或实测，保留能力缺口与尚待核实依赖。

按 [变更与回归](../atomic-to-fa-prd/references/change-and-regression.md) 维护行为差量与受影响交付闭环。下游未决产品决定由负责人收敛；研发任务附录按需给依赖和可观察验收。锁定正文模板哈希；本地回归只生成本地稿和待发布图源，不沿用历史原生图冒充新版交付。

统一用例遵循 [query 与测试集合同](../atomic-to-fa-prd/references/query-test-corpus.md)。维护唯一机器可读正本并由其导出独立飞书测试表（用户限定本地时导出待发布文件），视图不得独立改写预期。需求、规则、交互或两图变更时同步用例及映射，版本和哈希一并更新，由受影响角色重新验收；最终 review 纳入用例。测试表链接放附录，远端交付须同版回读；用户限定本地时只交本地文件，不创建或更新飞书。

调用独立 `fa-test-engineering` 专家；按 [测试执行与研发验收合同](../atomic-to-fa-prd/references/test-execution.md) 核对测试 Agent 实际消费回执、目标实现版本、逐例执行证据和关键规则正负验收。实现未提供时保留 blocked；独立 Agent 文本模拟可用于设计回归，真实实现验收需对应实现证据。修复后绑定新版重跑，正文模板与交付形式不变。

## 能力尽调交接补充

联用 `atomic-to-fa-prd/references/capability-gates.md`。消费能力专家的完整文档及示例覆盖、逐动作路径和验证证据；缺必要能力时缩小承诺或转能力缺口。产品、交互、测试与最终稿分别交能力专家实际独立验收，绑定同版产物哈希；修改后重验受影响部分。项目明确暂缓的需求保留现状，不扩展相关规范或用例。此补充只影响协作及附录，正文模板与交付形式不变。

## 四路发现与信息保全

按四路收敛同一功能正本；维护信息保全索引和变更影响，每次改动使受影响下游重新验收，未解决遗漏阻塞最终review。 交接执行 [信息保全合同](../atomic-to-fa-prd/references/information-continuity.md)，实际读取来源，逐项记录采用、转交、带限制或退回及对应位置；摘要不替代原始交付件。正文模板与飞书交付形式不变。

项目最终验收复用主 skill 的 [统一入口](../atomic-to-fa-prd/references/project-gate.md)；本角色变更交付件后更新引用和哈希，由受影响消费者重验。原始要求采用／合并／替代／暂缓的记录必须保留，不能只传阶段摘要。
